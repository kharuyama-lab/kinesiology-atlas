# 静止時からのACL/PCL前後関係（2026-11-02）

後続変更：[滑らかな表面への再構成](CRUCIATE_SMOOTH_SURFACE.md)。現在は元の付着中心と骨追従を保持し、表面を再構成している。以下は元の端部メッシュを残した前段階の記録。


## 原因の確認

当初、屈曲時の補間と相互接触の問題として説明したが、それだけではなかった。未変形のjoints.glbを別のGLTFLoaderで再読込し、修正前のMode 1 Anatomyと照合したところ、ACL840頂点・PCL420頂点は全て元GLBと一致した（最大差0）。表示上の入れ替えや名称の取り違えは確認されなかった。

元形状の端領域中心では、脛骨側のPCLはACLより後方にある（元座標z: ACL −0.026956、PCL −0.050989）。膝蓋骨はz +0.009386付近で、解剖学的前方が+zであることも照合。しかし、元GLB中央部の交差領域を前方から調べると、両者に当たる70本の検査線すべてでPCL表面が先に当たった。元モデルの中央走行にも今回の指摘に相当する問題があり、それを検証せず使っていた。

対象joints.glb SHA-256：9fdab1a257652597cf8f0b2ac93d12abc817e8f9a9099b9628e764018490afa2。

## 変更

- 名前・色の入れ替え、描画順・depthTestでの隠蔽はしない。
- 上記の確認済みGLBだけに、ACL/PCL中央部の走行補正を適用。他の手動読込モデルには自動適用しない。
- 元の両端カラーは固定。中央の断面中心の前方への張り出しを滑らかに減らし、付着端間の走行へ近づける。断面の幅を保ち、付着端近くでは補正を0へ減衰させる。
- 屈曲時に断面中心まで膝ピボット周りに補間する処理を、両付着端からの位置補間へ滑らかに置換。元の断面と骨への付着は保持する。
- 元データで共有されていた滑らかな法線を維持する。骨・半月板・膝蓋骨の運動、軸、UI、緊張表示は変更なし。

## 検証

構文PASS、ロジック24/24 PASS、実GLB関連UI4/4 PASS。

独立したGLB再読込による元付着端との比較、5靭帯×11肢位の追従を確認。Mode 1 Anatomy、Mode 2屈曲0/30/60/90/120°、90°で内旋15°・外旋30°の8肢位で、交差部の表面検査を実施した。脛骨の前方を基準に座標変換して検査し、画面のカメラ方向には依存しない。全検査肢位の重なりサンプルでACLがPCLより前方。データはcruciate-order-review.json、元形状照合はcruciate-source-rest-audit.json、画像はscreenshots/cruciate-order。

この検査は中央交差部の前後関係と元付着端の保持の確認であり、全表面の非貫通・骨面巻き付き・相互接触・生体張力・解剖学的最終FIXを承認するものではない。付着部位置を解剖学的に独立検証済みとは扱わない。

解剖学的位置関係の照合：[AAOS PCL anatomy](https://www.orthoinfo.org/diseases--conditions/posterior-cruciate-ligament-injuries)。
