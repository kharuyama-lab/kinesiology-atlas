実施日: 2026-10-30（日本時間）。Anatomy優先の開発版。関節中心・軸の解剖学的検証FIX前です。

## UI追補

### 読み込みがLoadingのままになる問題への対策

- 通常のEdgeでは報告された停止を再現できなかったため、原因をインターネット接続の有無と断定していません。従来はThree.js/Dracoの外部配信と、エラー表示開始前の静的モジュール読込に依存していました。
- Three.js 0.160.0とDracoデコーダーをライセンス付きで `vendor/` に同梱。ローカル確認は `.cache/` の保存済みGLBをクエリー指定なしでも自動優先し、外部通信なしで起動可能に変更。
- 依存ライブラリーを持たない `src/boot.js` から起動し、モジュール読込失敗をエラー/Retry表示へ。GLB取得8秒・復号15秒のタイムアウト、全体の監視を追加。無期限にLoadingを表示しないように修正。
- 起動時の文言から、原因をネット接続と決めつける案内を削除。ローカル配信にno-storeを指定し、配信サーバーを再起動。
- 検証: ロジック7/7 PASS、UI5/5 PASS。外部ホストを全遮断・モジュールのテスト差替なし・クエリー指定なしでReadyを確認。必須JSを404にした場合のエラー/Retryも確認。
- さらに実際のCodex内プレビュー `http://127.0.0.1:8080/?v=loadfix` でReady・3一括操作・閉じたIndividualを確認。ブラウザーのエラーログなし。[通信遮断時の起動確認](screenshots/local-loading-ready.png)
- GLBは引き続きGit/配布ZIPには同梱しません。公開ホスティングや別端末は外部取得または手動読込が必要です。

### 個別アコーディオンと膝運動時の筋追従

- Whole Bodyの各一括ボタンの下にIndividualアコーディオンを追加。骨・靭帯/軟骨・筋ごとに初期状態は閉じ、展開した場合だけ日本語・2列の個別操作を表示。
- 個別状態と3Dを同期。全件一致しないグループはMixedを表示し、一括ボタン1クリックで全件ONに復帰。Mode切替では開閉・個別状態を保持。Whole Bodyの明示ホーム操作では全件ON・閉じた状態に戻す。
- 右膝の観察肢位に筋が追従する模式的な変形を追加。Hip参照版の骨表面との距離による重み付けの考え方を、骨盤・大腿骨・脛骨の2関節の回転へ拡張。筋ごとの既存色、ON/Fade/OFF、同一メッシュを保持。
- 元のGLBを直接変形せず、複製した筋ジオメトリだけを更新。Anatomy復帰時は元の頂点配列を復元。非表示筋は更新を省き、再表示したときに現在肢位へ追従。変形更新は上限約30Hz。
- これは観察用の模式追従であり、実測起始/停止、筋長・筋力、巻き付き、接触、ひずみを再現・保証するものではない。関節中心・軸や靭帯動態をFIX済みに変更していない。
- 検証: 構文PASS、ロジック7/7 PASS、実GLB Edge UI 3/3 PASS。個別変更→Mixed→一括ON、開閉保持、筋の追従、元座標復帰、元ジオメトリの非改変、非表示後の再表示を確認。
- [全身の展開時](screenshots/whole-body-accordion.png)、[膝運動の筋追従](screenshots/knee-motion-compact.png)。

### Whole Bodyの3一括操作

- 全身の組織操作を骨／靭帯・軟骨／筋肉の3つに集約し、個別リスト・Selectionを非表示。ON→Fade→OFFの1クリック循環を維持。3Dから操作する場合もAll表示で同グループに一括適用します。
- 骨の軟骨部分は名称により靭帯・軟骨グループへ。これは既存の登録構造のグルーピング変更で、未登録の全身筋・靭帯を追加したものではありません。

## 修正した不具合・挙動

1. Hip/Knee Focusで骨盤等の骨格を隠していた処理を廃止。277骨格構造を常時保持。
2. Mode 2への変更が強制的にKnee Focus・初期角度・カメラへ戻していた処理を分離。ModeとFocusを独立状態に変更。
3. 独立Hip iframeのボタンを共通モードから除去。同じシーンのままHip Focusを保持。
4. 筋・靭帯・半月板は各組織ON→Fade（30%不透明）→OFF。プルダウン廃止。左行・選択欄・浮動操作で同期。
5. 広筋3筋の登録名に不足していた `muscle` を補完。大腿直筋を含む四頭筋4筋は実データに収録済みで有効化。
6. 複数プリミティブを持つ筋の子メッシュ名を解剖学的識別子と誤認しないよう、`extras.za_name` のみで親を解決。
7. 股関節の主要筋と靭帯を登録し、Focus別に関連組織を設定。二関節筋の特別な学習モードは追加していません。
8. 左骨格が右骨格を手前から覆う投影範囲で自動Fade。右骨格の不透明度は維持。
9. カメラの側方符号を左右大腿骨の位置で決定。右股・右膝中心をFocus基準にし、Whole Bodyも右股中心を基準に距離を調整。
10. Mode切替の肢位は補間。膝の移動分だけカメラとtargetを平行移動し、視線方向・ズーム・panを維持。
11. 右足部の骨格も下腿リグへ追従。手動GLB再読込は元データから再構築し、姿勢の二重適用・重複登録を防止。
12. 専門用語は日英表記、一般UIは英語。不要なRight接頭辞と独立したスクリューホーム等のトグルはありません。

## 再現手順

Node.jsとEdgeを用意し、`npm ci`。次の3ファイルを `.cache/` に保存します。GLBはGitにも配布ZIPにも含めません。

- https://nqwrc.github.io/3d-anatomy/models/skeletal.glb
- https://nqwrc.github.io/3d-anatomy/models/joints.glb
- https://nqwrc.github.io/3d-anatomy/models/muscular.glb

`npm run check`、`npm test`、`npm run test:ui` を実行。`test-results/` に画面を保存します。普段の起動は `npm run serve`。外部通信を使わず取得済みGLBで起動する場合は `/?localModels`、読み取り専用検証スナップショットを有効にする場合は `&qa` を付けます。

## 残る制約と次工程

今回完了した範囲はAnatomy v0.2とシームレス切替基盤です。Mode 2完成版ではありません。

- 関節中心は骨形状からの暫定推定。中心・運動軸を検証FIXするまでカメラ最終FIXと生体運動の正確性は未確定。
- Mode 2 Kneeは既存の模式運動を維持。股90°/膝90°、内外反時は膝30°。スクリューホーム・半月板・膝蓋骨は屈伸に従属しますが、軌道は未校正。
- 筋は元の静止メッシュのまま。Mode 2の曲がった肢位へ変形しません。靭帯は大腿側への剛体追従、半月板は脛骨への剛体追従、膝蓋骨は模式的な小移動です。力・張力の計算や生理的変形は未実装。
- Hipの完成済み運動UIは共通シーンに未統合。Hip FocusとModeの状態保持のみ対応。
- 左Fadeは境界箱の投影重なりによる近似で、厳密なピクセル遮蔽検出ではありません。
- 順序: 関節中心・軸検証FIX → カメラ最終FIX → 関節運動 → 靭帯動態。断面・二関節筋専用機能・CKC reverse actionは保留。
